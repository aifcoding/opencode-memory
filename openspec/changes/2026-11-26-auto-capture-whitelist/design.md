# 设计：规则采集正向白名单

## 1. 总览

```text
来源/安全检查
   │
   ▼
完整形态解析（六类解析器，任一成功才继续）
   │
   ▼
drop / pending / create / update
```

核心原则：**「关键词出现」只用于选择解析器，不能作为准入成功依据；解析不完整一律丢弃，不生成兜底候选。**

## 2. 六类记忆形态

| 类别 | 完整形态要求 | 写入级别 |
|---|---|---|
| 显式保存（E1） | 保存意图 + 正文完整自包含；正文须进一步匹配下列某类形态 | 见第 4 节 |
| 稳定配置绑定（S1） | 实体 + 白名单字段 + 合法值；整句无未解析残留 | 直写；冲突转候选 |
| 明确决策 | 作用域措辞 + 决策动词 + 具体选项 + 原因/适用背景，非问句非假设 | 候选（E1 直写例外见第 4 节） |
| 长期约定/偏好 | 主体 + 对象 + 行为 + 持续性词（以后/统一/禁止/不要/默认/一律） | 候选（E1 直写例外见第 4 节） |
| 明确纠正（C1/C2） | 实体 + 字段 + 新值 + 纠正关系；更新还须旧值可核对 | 满足条件走 C1 更新，否则候选 |
| 可复用根因/方案 | 结构化模板：适用问题 / 根因 / 处理 | 候选 |

约束：

- 显式「记住」表示保存意图，不是绕过内容完整性的通行证；`记住这个`、`记住：重启电脑吧` 不采。
- 配置字段沿用有限类型集合（endpoint/port/version/path 等）；URL、端口、路径、版本必须绑定实体与字段，裸值不采。
- 仓库按命名配置绑定；命令只接受「项目/用途 → 固定命令」的明确映射，默认候选，且绝不执行。
- 根因/方案只认模板；自由叙述交给 LLM 管线。

## 3. 与现有规则的映射

| 现有规则 | 处理 |
|---|---|
| E1 显式保存 | 保留保存意图；正文接入形态解析；纯指代不直写 |
| E2 弱 explicit | 删除弱关键词兜底；有效内容归入偏好/配置等形态 |
| S1 完整绑定 | 保留；唯一自动新增直写入口 |
| S2 不完整结构化 | 删除「不完整就候选」；只保留完整绑定的冲突候选 |
| D1/D2 | 合并为完整决策解析；统一候选 |
| C1/C2 | 共用完整纠正解析；C1/C2 只表示更新是否安全，不表示内容是否完整 |
| Q | **删除采集分支**；历史枚举/标签保留兼容读取，不再产生写入 |
| N | 所有未匹配、解析不完整、语义不确定内容的默认结果 |

## 4. 直写出口

```text
直写：
  - S1 新增：一个确定的实体—字段—值，无冲突
  - C1 更新：完整纠正 + 旧值核对 + 唯一目标 + 目标为 agent/low + CAS 成功
  - E1 + 完整配置绑定（归一为 S1）
  - E1 + 完整决策 / 完整约定（产品折中，见决策记录）

候选：
  - 完整决策 / 完整约定（非 E1）
  - 完整但不能安全更新的纠正
  - 配置绑定冲突
  - 根因/方案模板命中

丢弃：
  - 不完整、纯指代、临时安排、问句、假设、hedge
```

### 4.1 决策记录：E1 决策/约定直写

- 架构师意见：反对。理由——作用域未实现（当前全部 `global/default`）、条件与作用域容易在解析中丢失、低信任标签不能阻止召回污染；建议只允许「E1 + 配置绑定」直写。
- 产品决定：接受「E1 + 完整决策/约定」直写，以降低审批摩擦；以「完整解析才直写」作为补偿。
- 回滚条件：会话/项目作用域分层落地后重新评估；若出现错误直写污染召回，立即回退为仅候选。

## 5. 必须保留的闸门

1. **来源闸**：仅可信人工输入进入规则采集（origin 校验）。
2. **陈述状态闸**：问句、提议、假设、待确认事实不自动持久化；六类一视同仁，不允许 correction 抢先绕过。
3. **凭据闸**：沿用脱敏与风险检查；脱敏后的 `[REDACTED]` 不能作为合法配置值重新通过。
4. **资源与写入闸**：大小、条数、幂等、冲突保护、CAS。

删除：Q 专用确认语黑名单、弱 explicit 关键词兜底、「含 URL + 字段词就候选」、来源可信后仅凭正文形态判断作者身份的逻辑。

## 6. 实现结构

```ts
type MemoryForm =
  | { kind: 'binding'; entity: string; field: string; value: string }
  | { kind: 'decision'; scope?: string; choice: string; basis: string }
  | { kind: 'preference'; scope?: string; subject: string; action: string }
  | { kind: 'correction'; entity: string; field: string; old?: string; next: string }
  | { kind: 'solution'; problem: string; cause: string; remedy: string }
  | { kind: 'explicit'; statement: string };
```

- 每类一个解析函数，返回结构化结果或 `undefined`；不提供「部分命中生成候选」的统一 fallback。
- 字段别名与值类型采用表驱动。
- 显式保存先解析意图，再解析正文；正文命中纠正语义时优先走纠正解析。
- 多义或未完全消费输入 → 丢弃。

防补丁纪律：新增准入必须说明完整形态、必需字段、写入级别，并提供一正一反例；只有一个噪声例不得新增业务黑名单。

## 7. 迁移与清理

- 先 shadow：新旧规则并行计算，只记录差异，不写库；对比通过后按配置启用。
- 不自动重放历史会话。
- 现有噪声候选（18–23、32–38）：逐条核对来源与内容，仍 pending 且确认噪声的走 `reject`（保留审计），不直接删库。
- 旧规则产生的正式记忆不做批量回滚；按「来源规则 + 原文 + 修订记录」生成待清理清单，经用户确认后逐条软删。

## 8. 验收矩阵

| 类别 | 正例 → 预期 | 反例 → 预期 |
|---|---|---|
| 显式保存 | `记住：本项目发布前必须先跑 e2e` → 候选 | `记住这个` → 丢弃 |
| 配置 | `probe.port=18093` → 直写 | `probe.port=65536` → 丢弃 |
| 决策 | `本项目已决定采用 SQLite，原因是离线部署` → 候选 | `是否应该采用 SQLite？` → 丢弃 |
| 约定 | `本项目以后统一使用 Bun 运行测试` → 候选 | `以后都这样` → 丢弃 |
| 纠正 | `更正：probe.port 从 18093 改为 18094` → 满足条件更新 | `配置类的应该是以后用得着的就沉淀长期记忆？` → 丢弃 |
| 根因方案 | `适用问题：连接池耗尽；根因：未释放；处理：finally 释放` → 候选 | `因为太慢了` → 丢弃 |

四条真实噪声必须断言「正式新增 0、候选新增 0、revision 不变」：
`重启电脑吧`、`这个测试是干嘛的`、`当然是按最优架构来`、`我系统内存现在还是显示在高位`。

交叉用例：

- 上轮助手问句 + `深蓝色` → 不因 Q 持久化。
- `项目X.测试命令="bun test"` → 候选；裸 `bun test` → 丢弃。
- `如果 probe.port=18093，会怎样？` → 丢弃，不能拆分后命中。
- 同键异值 → 候选不覆盖；重复重放 → 不新增、不增 revision。
- 同正文人工 / automation → 只有人工有资格进入白名单。
- shadow / off → 两类存储均无写入。
- 候选审批前不进入召回，审批后才进入。
