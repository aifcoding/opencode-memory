# 规则采集改为正向白名单

## 问题

规则采集不是缺少几条噪声过滤，而是存在**弱信号也能落候选**的兜底入口：

- Q 规则仅凭上一轮助手问句就为用户短回复生成候选（`AutoCaptureService.ts:662-679`）；而 `admission-rules.md:52` 写的是「`qa` 不再产生任何持久化」，文档与代码矛盾。
- C2 在实体/字段解析失败时仍生成候选（`AutoCaptureService.ts:393-409`）。
- S2 允许「结构化值 + 字段关键词」即候选；E2 允许弱关键词命中（`AutoCaptureService.ts:637-658`）。

真实噪声：`重启电脑吧`、`这个测试是干嘛的`、`当然是按最优架构来`、`我系统内存现在还是显示在高位`、`…配置类的应该是以后用的着的就沉淀长期记忆？`。

黑名单式补丁无法枚举全部噪声，且每加一条就多一个特例。

## 方案

规则采集改为**正向白名单**：只有完整解析出「记忆形态」的输入才准入，其余一律丢弃；候选不是未匹配内容的垃圾桶。

六类记忆形态：显式保存、稳定配置绑定、明确决策、长期约定/偏好、明确纠正、可复用根因/方案。

- 只保留两个自动直写出口：新增配置绑定（S1）与完整纠正更新（C1）；另有产品折中：显式保存（E1）正文若完整解析为配置绑定/决策/约定，允许直写。
- 显式保存只表示保存意图，不单独提高解析结果的写入权限；正文不完整、纯指代、临时安排一律不采。
- 删除 Q 持久化、E2 弱关键词兜底、S2 不完整候选、C2 无完整解析的兜底。
- 统一闸门：来源、陈述状态（问句/假设/临时）、凭据、资源与幂等。

## 影响

- `AutoCaptureService` 从「分支式规则 + 兜底」改为「解析器注册表」；新增 `MemoryForm` 结构化结果。
- 规则编号与文档同步：Q 删除；E2/S2 收窄；C1/C2 共用完整纠正解析；E1 接入形态解析。
- 自动采集可能漏采自由表达；兜底方式是用户显式补全（`记住：具体事项`）或手动 `memory_capture` 交给 LLM 管线，不自动把未匹配内容送模型。
- 不改变 LLM 提取管线与召回路径。

## 非目标

- 不做会话级/项目级作用域分层（另立变更）。
- 不自动重放历史会话，不批量回滚旧规则产生的正式记忆。
- 不把白名单限制迁入 LLM 管线。

## 风险

- 误杀：有价值但不符合形态的自由表达不会再自动采集；需在文档与提示中明确「补全 + 手动提取」。
- 决策/约定直写依赖文本作用域，当前所有记忆仍为 `global/default`；错误直写会被自动召回（标记未确认）。
- 解析器注册表增加维护成本，需要纪律：新增准入必须给完整形态、字段与正反例。
