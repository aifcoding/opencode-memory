# 自动采集准入规则（矩阵 v1）

状态：已与架构师对齐，待实现。实现前不得再用「发现噪声→加正则」方式扩展规则。

## 0. 统一处理规则

1. 只判定真实用户消息原文；排除代码块、引用块、系统注入（`mem_block`/`system-reminder`/`background-result`/`fork-notice`/`subagent-update`）。
2. 逐个文本单元判定，不继承整段信号；例外：显式「记住：……」保留为单个完整单元，不拆条。
3. 凭据：命中片段脱敏为 `[REDACTED]` 后继续采集/提取；只有「整条消息/全部材料仅由凭据构成」时才放弃；`password=环境变量`、`***` 等占位符不脱敏（不承诺识别全部秘密）。
4. 更新（C1）优先检查目标；不因 explicit 命中而绕过纠正契约。
5. 同实体同字段出现新值且无 C1 依据时，只允许生成候选，禁止自动覆盖；**任何非 C1 路径都不得按 title 覆盖既有记录**，同一条消息内的重复标题同样降级为候选。值比较必须按边界匹配（`1808` 不命中 `18080`）。
6. 直写单元必须且只能有一个确定的「实体—字段—值」绑定。
7. 代码围栏（```）与引用块（`>`）内的内容一律不参与判定。
8. C1 必须给出白名单字段与通过类型校验的新值，目标按标题 token 精确匹配且唯一。
9. 自动采集产生的条目若标题只是单个宽泛词（无 `. : / =`），不参与自动召回注入。

## 1. 准入矩阵

字段白名单（v1 固定）：地址/url/endpoint、端口/port、版本/version、路径/目录/path。

| 规则 | 可判定条件 | 处理 | 必须挡住的负例 |
|---|---|---|---|
| E1 明确保存 | 单元以 `记住/记一下/保存下来` 开头；后有分隔符或空白及非空正文；正文 ≤400 字；非问句；不含否定开头（不要/别/不用）；正文不是纯指代 | 按形态解析：完整配置绑定→直写（归一 S1）；完整决策/约定→直写；其他完整正文→候选；不完整/纯指代→丢弃 | 「不要记住这个地址」；「记住：不要保存这个」；「记住：A=1。B=2」→候选；「记住这个」→丢弃 |
| E2 弱 explicit | **已删除**（弱关键词兜底不再准入） | 不产生写入 | 「配置是 redis.internal:6379」→丢弃；「以后都这样」→丢弃 |
| S1 完整配置 | 整个单元匹配 `实体.字段=值` 或 `实体（含中文名词）的字段是值/为/=/：`；字段在白名单；值通过类型校验（URL/host:port/端口/版本/绝对路径，且不含问号感叹号）；无额外分句；非问句；不含示例/假设语气 | 直写；同键异值、同 title 异内容则候选 | 「看看 https://example.org 怎么打不开」；「如果升级到 1.2.3 会怎样？」；「服务地址是 https://example.org？」；「示例地址是 https://example.org」 |
| S2 不完整结构化 | **已删除**（不完整不再产候选） | 不产生写入 | 裸 URL、裸路径、裸版本、非法值 → 丢弃 |
| D1 明确选型 | 整个单元匹配 `本项目[已]决定采用 X` / `项目<标识符>[已]决定采用 X`，X 为单个标识符或引号名称，无额外分句 | 直写 decision | 「是否决定采用 SQLite？」；「如果本项目决定采用 SQLite，就…」 |
| D2 其他决策 | 命中 `决定/采用/否决/放弃` 且含明确实体与选择项 | 候选 | 「这次不用跑全量测试」→丢弃；「因为太慢了」→丢弃 |
| C1 可验证纠正 | 实体+字段+新值明确；唯一匹配一条 `agent/low`；给出旧值时旧值必须出现在该条正文；CAS revision 匹配 | 更新该条；内容相同则不写 | 「改成新版」→不得更新；目标为 `user/*` 或 `trust=high` → 不得更新 |
| C2 无法安全纠正 | 纠正内容完整，但匹配 0 条/多条/旧值不符/目标非 agent-low | 候选；不新增替代事实、不覆盖 | 「更正一下」→丢弃；「不是这个」→丢弃 |
| Q 仅问答对 | **已删除**（不再产生任何写入） | 不产生写入 | 「深蓝色」「重启电脑吧」→丢弃 |
| N 无有效单元 | 未命中以上 | 丢弃 | 「好的」；「你再看看」 |

## 2. 写入路径

- 直写：沿用 `storeMemory`（`origin=agent`、`trust=low`、tags 含 `auto` 与 `auto:<signal>`）。同 title 已存在且内容不同时**不覆盖**：降级为待审候选（`skipped`/`reason=title conflict`）；只有 C1 可更新既有记录。
- 候选：复用现有采集管线 `beginCapture → completeCapture`，写入 `memory_candidates`（`status=pending`），审批沿用 `reviewMemoryCandidate`。
- `memory_capture_runs.trigger` 需新增取值 `auto`（当前 CHECK 仅允许 `compaction/manual`），需一次迁移；`extractor_version` 记 `auto-v1`。
- 未审批候选不在 `memories` 表，默认召回与 `memory_recall` 天然不返回。

## 3. 限流与去重（初值，需固定测试）

- 单条消息最多 3 条直写；超出的单元转 pending 候选（不再丢弃）并记录原因。
- 同一 scope 每日最多 20 条新增待审候选；超出记入 `skipped`。
- 候选按 `(capture_key, content_hash)` 去重；重复内容不刷新时间。
- 14 天过期：本期**未实现**（需要 `expired` 状态与迁移），在文档标注为已知缺口。

## 4. 配置

- `autoCapture.mode`: `off | shadow | on`（`on` = 按本矩阵直写 + 落候选；`shadow` = 只计算不写）。
- 不提供 `directWrite` 布尔开关（会变成「跳过闸门」）。
- `qa` 不再产生任何持久化；`AUTO_SIGNALS` 中 `qa` 仅保留枚举值用于潜在扩展。

## 5. 验收用例（每格至少 1 正例 + 表中负例）

断言需同时检查：`memories` 行数/revision、`memory_candidates` 行数与 `status`、召回结果。

1. E1：`记住：probe.port=18093` → 正式 1 条；`记住 测试库在 10.0.0.5:3306` → 候选 1；`记住这个` → 两库均 0。
2. E2 弱兜底已删除：`配置是 redis.internal:6379` → 两库均 0。
3. S1 `staging.redis.endpoint=redis.internal:6379` → 正式 1 条；排查 URL、假设版本、端口 65536 → 正式 0 条。
4. S2 已删除：不完整结构化（`staging.redis.endpoint` 无值）→ 两库均 0。
5. D1「本项目决定采用 SQLite」→ 正式 decision 1 条；问句/条件句 → 0。
6. D2「本项目否决 SQLite，原因是并发写入限制」→ 候选 1；「这次不用跑全量测试」→ 0。
7. C1 唯一低信任目标 + 明确新值 → 只更新该 id、revision+1；目标为 user/high → 不更新。
8. C2 两个匹配目标/旧值不符 → 候选 1，原记录全部不变。
9. Q 已删除：上轮问颜色、本轮「深蓝色」→ 两库均 0；`重启电脑吧` → 0。
10. N 普通对话 → 0；「好的」「你再看看」→ 0。
11. 交叉：E1 内含纠正不得绕过 C1/C2；同键异值不得靠标题命中覆盖；有效配置后附「你再看看」不得继承信号；qa 与 S1 同时存在按 S1 留存；同内容重放不新增、不递增 revision。
12. 候选审批前旧正式记录与召回结果不变；审批后进入正式记忆并可被召回。
13. 凭据：整条仅由凭据构成 → 两库均 0 新增；凭据与其他内容混合 → 脱敏为 `[REDACTED]` 后按正常规则处理。
14. `shadow` → 两库均 0 写入；`off` → 不计算不写。
