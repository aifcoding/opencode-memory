# 设计：记忆指令执行器

## 1. 行为定义

| 输入 | 规则 | 写入 |
|---|---|---|
| `记住/记一下/保存下来` + 正文 | E1 | 立即直写；整条消息作为**一条**记忆 |
| 无显式保存的行为指令 | N | 不写入；需要保存时用 `记住：…` |
| 明确纠正（`不是X是Y` / `改成Y`），目标唯一且旧值相符 | C1 | CAS 更新；失败则丢弃并提示 |
| 其他一切（随口配置、日志、决策句、问答对） | N | 规则层零写入（不采、不产候选） |

## 2. 安全边界（「无条件」= 不做质量审批，不是绕过安全）

1. 来源必须是可信人工输入；automation / 引用 / 日志 / 插件注入中的「记住」不执行。
2. 凭据脱敏后仍有正文 → 保存脱敏版本；仅剩凭据 → 丢弃并明确告知未保存。
3. 对象/目标必须可确定；`记住这个` 且无唯一结构化对象 → 不保存、不产候选（提示澄清）；上有唯一结构化对象时按该对象保存。
4. 大小、权限、CAS、存储失败 → 明确失败反馈；**不得静默转候选**。显式指令不受 `maxWritesPerTurn` 截断。
5. 正文质量不设闸：问句、单字、代码块、缩进都按原文保存；同标题不同正文新建唯一标题条目，不覆盖既有记忆。

## 3. 实现位置

- `core/application/AutoCaptureService.ts`
  - `routeUnit`：只处理显式保存、行为指令、明确纠正
  - `routeText`：显式保存整条消息不切句；非 N 结果只进直写
  - `routeCorrection`：C2 失败分支改为丢弃
- 删除：S1/D1/D2/E2/Q 隐式分支、`BINDING_ENTITY`、隐式候选与长度兜底、纯指代待审候选。

## 4. 配置语义

- `autoCapture.enabled`：是否执行明确记忆指令（默认 true）。
- `mode=on`：明确指令立即写入/更新。
- `mode=shadow`：仅诊断、不写库、推进游标；启用时必须提示「观察模式，未保存」。

## 5. 保留

来源准入、凭据处理、资源限制、幂等/去重、C1 的旧值核对与 CAS、LLM 提取、规则 md、候选审批、召回、写入结果返回记忆 ID。

## 6. 验收矩阵

| 场景 | 预期 |
|---|---|
| `记住：发布前先跑 e2e` | 正式 1、候选 0、可检索 |
| `记住：<多行粘贴>` | 正式 1（整段一条）、候选 0 |
| `以后都用中文回答` / `本项目统一使用 Bun` | 正式 1、type=preference |
| `记住：发布前要跑 e2e 吗？` / `记住：甲` | 保存原文（不做质量闸） |
| `记住：` + 代码块 | 整段保存，代码围栏/缩进保真 |
| 同标题不同正文（`port=3306` → `port=3307`） | 新增唯一标题条目，不覆盖、不转候选 |
| 普通聊天纠正（无记忆意图） | 不改写任何记忆 |
| `记住这个` | 两库 0（对象不明确） |
| `不要记住这个` | 两库 0 |
| `默认端口是什么？` | 两库 0 |
| 无指令的 `probe.port=18093` / npm 日志 | 两库 0 |
| automation 发送 `记住：…` | 两库 0 |
| 明确纠正 + 唯一目标 + 旧值相符 | 同 ID 更新、revision+1 |
| 纠正目标不明/多目标/旧值不符 | 明确失败/丢弃，不误改、不转候选 |
| 仅凭据的显式保存 | 两库 0，并提示未保存 |
| 重复 hook 同一消息 | 不重复写入、不增 revision |

真实链路必验：显式保存落正式库并可检索、automation 区分、纠正同 ID 更新、失败反馈。

## 7. 明确接受的残余

- 同一行文本（手写 vs 粘贴）无法区分；显式 `记住：<粘贴内容>` 按用户要求保存为一条记忆，这是产品选择。
- 隐式内容不再自动发现；依赖压缩/手动 LLM 提取，LLM 关闭时不会自动发现。
