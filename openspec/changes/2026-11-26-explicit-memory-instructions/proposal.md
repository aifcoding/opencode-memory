# 规则采集改为「记忆指令执行器」

## 问题

规则采集原先同时做两件事：识别用户明确的保存指令、以及**自动推断**哪些内容值得记（S1/D1/D2/E2/Q 等隐式规则）。第二件事需要从纯文本判断意图与价值，导致：

- 粘贴的终端输出被当成配置直写（`npm notice version: 2.4.0-rc.3`，memory id=128）
- 每补一类噪声就多一层规则（实体形状、块分段、直写/候选分档），复杂度持续上升
- 隐式候选占用审批队列，且候选不参与召回，价值延迟

纯文本无法区分「用户手写 `probe.port=18093`」与「粘贴输出中的同一行」，继续加正则无法收敛。

## 方案

规则层改为**只执行用户明确的记忆指令**，隐式内容规则层完全不采：

- 显式保存（`记住/记一下/保存下来 + 正文`）→ **立即直写**，不评价价值、不降候选；整条消息作为一条记忆；正文保真（代码块/缩进/换行），不按问句/长度/字数筛选；同标题不同正文新建唯一标题条目。
- 完整顶层行为指令（`以后/下次/统一/禁止/默认/一律/全部`，可带「本项目」前缀）→ 立即直写为偏好。
- 明确纠正（带 `更正/改成/记住` 等意图 + `不是X是Y` / `改成Y`）→ 目标唯一且旧值相符时更新（CAS）为新值；无法确定则丢弃并提示；普通聊天纠正不改写记忆。
- 其余内容（随口配置、日志、决策句、问答对）→ 规则层零写入，交由压缩/手动 LLM 提取产生候选。

安全边界不放宽：来源必须是可信用户（automation/引用中的「记住」不执行）、凭据脱敏（仅凭据时明确告知未保存）、对象/目标可确定、大小/权限/CAS 失败明确反馈、失败不静默转候选；显式指令不受 `maxWritesPerTurn` 截断。

## 影响

- `AutoCaptureService` 只保留显式保存、行为指令、明确纠正；删除 S1/D1/D2/E2/Q 与隐式候选分支。
- 旧白名单变更（`2026-11-26-auto-capture-whitelist`）被本变更取代。
- 规则层不再产生候选；候选只来自 LLM 提取（压缩/手动）。
- 文档、测试、`admission-rules.md` 同步。

## 非目标

- 不改变 LLM 提取管线、候选审批、Pin、召回。
- 不做粘贴/日志来源识别或内容评分；接受「同一文本不同意图」的残余歧义。
- 不为隐式内容保留低噪声候选旁路。
